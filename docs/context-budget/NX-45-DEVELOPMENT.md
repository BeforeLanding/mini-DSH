# NX-45：两臂开发探索冻结协议

状态：零付费准备。协议 ID 为 `NX-45-dev-2arm-v1`，仅用于探索性开发诊断；不并入 NX-42 的校准或正式 240 episode，也不改写 NX-44 smoke 结果。运行前须从最终干净 HEAD 生成独立 manifest，证据根目录必须尚不存在。本阶段真实模型请求为 0；24 次运行需单独金额授权。

## 任务与历史曝光

选择规则先看任务类别和信息形态：五个已有校准根问题各取一个，覆盖五类任务；再取正式候选池按 ID 排序的第一个短任务 `U01`。没有使用任何历史 Baseline/Full 胜负作筛选。六题是**开发集**；`U01` 一旦用于本协议，就不能继续称作未接触的正式留出题。后续正式题库及其分母须另行重新冻结，旧 240 项清单不充作新的留出试验。

- `UC01`，代码理解/复现，四阶段同步器：检验跨阶段保留与撤销约束。既有真实记录 26 条，Baseline/Full 各 13；高度曝光，明确属开发题。
- `BC01`，Bug 修复，大信息日界线日志：检验定位与跨时区边界。既有真实记录 28 条，两臂各 14；开发题。
- `FC01`，功能实现，大信息开关依赖闭包：检验多模块定位、环与缺失依赖。既有真实记录 27 条，Baseline 13、Full 14；开发题。
- `RC01`，重构，四阶段队列/堆迁移：检验跨阶段共享预算和旧实现退役。既有真实记录 28 条，两臂各 14；开发题。
- `TC01`，测试编写，大信息 Webhook 重放日志：检验正确实现与变异体的行为区分。既有真实记录 28 条，两臂各 14；开发题。
- `U01`，代码理解/复现，短配置优先级缺陷：补齐短任务锚点。此前八批 NX-42 真实 `runs.jsonl` 中无 `U01`；它原在正式候选池，但本次纳入后改归开发集，不再作为未曝光留出题。

`meta.json` 固定每题四组独立验收。冻结前用现有隔离 fixture 测试核对每题初始态失败、参考态通过、两种反例失败；UC01/RC01 另核对四个阶段参考态。候选工作区不含隐藏 `verify.mjs`、参考解或 oracle；验收只在候选退出并保存快照后，对隔离副本执行。

## 两臂与整题预算

沿用 v2.1 同一装配、模型、工具 schema、自动审批、隔离运行器和题目。Baseline 关闭主动历史裁剪与压力压缩（输入目标及主动压缩预算均为 1M）、使用 live 提示前缀和无界预览配置；它**仍保留**窗口溢出时的一次兜底压缩、相同的 `read_tool_result` 回读工具、预算与安全检查。Full 的输入目标与压缩预算为 65,536、压力比例 0.8，使用默认 16 KiB 工具预览与会话内冻结前缀。白名单恰为 `budget.inputTargetTokens`、`budget.compactionBudgetTokens`、`toolOutput.bounded`、`promptLayout.frozen`；其余预算、工具/schema、权限、模型和验收器相同。Full 不增发反馈、工具、重试或摘要额度。

每个**完整 episode** 共享 1,000,000 累计 token、64 次模型请求（主请求及摘要合计）、128 次工具调用和 600 秒主动时间。`runV2Stages` 在每阶段前扣减已用量，整题 watchdog 跨阶段运行；阶段结束的非 `completed` 状态不发下一阶段。现有单请求上限为 180 秒、最大输出 16,384 token、最小输出预留 4,096 token；Bash 30 秒，审批 300 秒，收尾 5 秒。四阶段题没有四份整题预算。这个 1M 档只为本次开发探索，不能泛化为所有模型的合适预算。

模型请求为 `deepseek/deepseek-flash`（provider model ID `deepseek-flash`，预期回显同名），官方页面本次标示版本 `DeepSeek-V4.1-Flash-1017`；thinking 明确 enabled，1M 窗口，流式调用。采样沿用**provider-default**：适配器不发送 temperature 或 top_p；官方说明思考模式下 temperature 不生效，`deepseek-flash` 的 top_p 仅在 0.95–1.0 范围生效，故不假称温度可控或固定随机种子。冻结前和执行前须再次核对[官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)及[思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)；版本或价格变化需重冻结。

## 固定 24 项日程

六题 × 两次重复 × 两臂 = 12 个相邻 block、24 条 episode。种子 `20261017` 只固定任务和两臂顺序，不控制模型采样。每个 block 先后如下；重复编号从 0 开始：

1. `UC01/0` Baseline → Full
2. `BC01/0` Full → Baseline
3. `RC01/0` Baseline → Full
4. `TC01/0` Full → Baseline
5. `U01/0` Baseline → Full
6. `FC01/0` Full → Baseline
7. `BC01/1` Full → Baseline
8. `TC01/1` Baseline → Full
9. `UC01/1` Full → Baseline
10. `U01/1` Baseline → Full
11. `FC01/1` Full → Baseline
12. `RC01/1` Baseline → Full

两臂各先行六次。每个 block 必须两条同题同重复；余额不足整块的保守预留时，不启动该 block。不得因前一臂的成败改变后一臂题目、反馈或预算。

## 停批与报告

主口径是可靠完成：runStatus=`completed`，最终产物独立验收 `passed`、四组合同全过、受保护文件未改且证据完整，缺一不可。产物验收单独列：预算停止时即使退出候选已正确，也只计 `artifactAccepted`，不计可靠完成。每臂固定计划分母 12；未运行项列 missing，报告 incomplete 并给 0/1 范围，不缩分母。六题是开发探索，配对差值与区间只作描述，`interpretation=development-only`，不宣称正式改善或可泛化的胜率。

正常任务失败（公开/自写检查失败、产物不通过、输出/请求/工具/token/时间预算停止）记录原因后继续同 block 的下一条及后续 block。模型/provider/运行基础设施故障、缺失或非 provider usage、候选快照/日志/验收证据异常、价格闸门拒绝或已知累计费用超限则停批，不以估算 usage 充当零费用。`runs.jsonl` 每条保留 status、独立验收、四合同、累计用量、机制读数及错误原因；`report.json` 固定包含协议与摘要、planned/executed/missing/invalid、每臂可靠完成/产物验收及范围、失败分类、模型/工具/token/延迟/机制、逐题配对、探索性主差值、费用账本和测量限制。异常批次标 incomplete，不补跑或删失败。

## 价格与金额建议

2026-10-17 的[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)显示 `deepseek-flash` 峰时每百万 token：缓存命中输入 `$0.006`、未命中输入 `$0.30`、输出 `$1.20`；离峰为峰时一半。冻结使用峰时快照，不假设运行一定落在离峰。既有三批 1M 校准共 60 条（Baseline/Full 各 30）按本价格重算为 `$5.876914176` / `$1.588002996`；按 12+12 同均值投影约 `$2.99`，因此**预期量级约 `$3–5`**。这些批次只含五个 C 题、代码和模型版本可能不同，U01 尚无真实用量；它们是规模参考，不是对本批的费用预测保证，也不是拿 NX-44 短 smoke 线性外推。

保守预留逐条按 1M token 全以最高输出价 `$1.20`、另加 20% `$0.24`，再加一次可能跨越累计 token 闸门的最大请求（1M 输入 `$0.30` + 16,384 输出 `$0.0196608`），合计 `$1.7596608`/episode。24 条 `$42.2318592`，协议探针预留 `$0.0196608`，合计 `$42.25152`；**建议单批金额授权上限 `$43`**。这是保守的门槛，含明显重叠，不是预计实际账单。运行器在每次请求前按 1M 输入和当次输出上限预留，使用 provider usage 逐次累计；usage 未知停批。价格、模型版本、缓存命中和长题实际用量均可能变化，执行前必须重新核价与确认该批独立授权。

## 冻结与执行交接

冻结产物在仓库外独立目录，必须对应最终干净 HEAD，含代码 SHA、六题全部文件 SHA、工具 schema SHA、模型/版本、thinking、采样、1M 预算、价格快照、固定 24 条顺序和 manifest digest。`--validate-only` 核对 digest、HEAD、文件、schema、日程、WSL/bwrap 预检，不读取密钥或调用模型。真实 `--execute` 先做同样校验，之后才读取凭证并作协议探针；本阶段不得执行。准确绝对路径、digest 与命令在最终冻结后记录于交接回复，避免把将变化的 HEAD 写进本协议正文。
