# NX-42：20-task Harness Benchmark v2 测试方案

日期：2026-10-15。状态：方案已确定，代码、题目和真实模型批次尚未实施。本文件经 PLAN 的 NX-42 节纳入设计规范；不代表已有实验结果或已完成预注册。

## 1. 本次确定的选择

建立独立的 `harness-v2`：20 个独立问题，代码理解、Bug 修复、功能实现、重构、测试编写各 4 题；Baseline / Context Manager / Prompt Optimizer / Full Harness 四组对照；每题每组 3 次独立尝试，共 240 个 episode。一个 episode 是从干净工作区开始、包含全部阶段的一整题。

主问题：同一模型、权限、工具与整题资源预算下，Full 相对 Baseline 的可靠完成率是否改善。其余两组用于解释两项处理的作用，不预设结果为 75%→90%，不承诺 Full 胜出。

旧 `screeningIds`、`ablationIds`、NX-08/NX-38/NX-39 及原始日志保留；新批次不覆盖旧目录、不重算后冒充旧协议结果。现有 NX-40 成功率排除预算停止的读数仍属旧口径。

本次只确定方案、同步规范和列实施步骤，不创建 fixture、不修改生产行为、不启动模型调用。旧 NX-41 是一种历史依赖压力任务的候选设计，可提供题目素材，不是本题库每题必须满足的条件。

## 2. 四组的唯一区别

处理 C 为上下文管理复合能力：历史任务裁剪、主动压缩、工具结果预览有界；处理 P 为提示前缀稳定。四组为 Baseline=(C关,P关)、Context Manager=(C开,P关)、Prompt Optimizer=(C关,P开)、Full=(C开,P开)。

- C关：复用当前 `ablationPolicy`，输入目标及主动压缩预算设为共同的已核验模型窗口；工具结果预览使用当前无界评测配置。保留当前溢出兜底压缩。因此准确名称是“不主动管理的 Baseline”，不是“毫无上下文处理”。
- C开：输入目标 65,536；主动压缩预算 65,536、比例 0.8（阈值 52,428.8，实际以源码比较为准）；工具结果预览复用当前生产默认 16 KiB。保留摘要、历史及工具结果回读。
- P关：`runtime-context` / `project-context` 的 `live` 布局。
- P开：相同插件的 `frozen` 布局；只冻结系统提示中的材料，`project_context` 工具仍实时读取。

四组均使用 `profile: coding`、相同工具 schema、相同初始规则与权限。文件与 Bash 的策略、保护文件范围、审批配置完全相同。不得给 Full 额外规划提示、工具、隐藏检查反馈、请求额度或免费摘要调用。

两档提示在共同的逻辑起始时刻、同一工作区上首帧内容应相同；真实批次各自时钟可能不同，保留时间字段并比较允许差异集合，不能声称实际首帧哈希必然相等。P主要研究缓存与资源，不要求正确率上升。Full 仍是实验组合，尚不能称为当前 CLI 默认配置。

模型沿用项目现有 DeepSeek 适配器；在校准开跑前固定明确 model ID、端点、供应商回显/版本、thinking、采样参数、真实窗口、Node/OS、锁文件和代码 SHA。当前适配器未发送 temperature/seed，不假装已固定解码。若核验窗口不大于 65,536，本版本不适用，应先修改协议。主批次不人为缩小真实模型窗口。

## 3. 20 题目录与验收合同

下列为题目合同设计，不是已落地的 fixture。每类依次为基本题 S、跨模块题 M、大信息定位题 O、多阶段题 L。合计 5S+5M+5O+5L；S/M/O 均一个 `send`，L 为同一 session 的四个 `send`。每个新根问题使用独立初始项目，不能把同一缺陷的四个改名版本算四题。

### 代码理解：U01～U04

- U01 配置优先级复现（S）：追踪默认值、文件与显式参数的合并，提交 `repro.mjs`，在缺陷实现失败、正确实现及两侧行为等价改写中保持对应结果。
- U02 跨模块异步失效定位（M）：追踪请求、重试、缓存的调用链，提交定位与行为复现；验收主体是可执行复现，不用主观文字评分。
- U03 请求日志与源码关联（O）：从多请求混合日志及多个实现候选中复现错误分支；验收不同请求 ID、顺序及无关记录变化，不能硬编码某行日志。
- U04 规则演进后的影响分析（L）：四阶段依次解释并复现当前行为、加入规则变更、处理兼容要求、提交完整回归复现；终态产物必须覆盖当前合同并拒绝已撤销规则。

### Bug 修复：B01～B04

- B01 分页边界与空输入（S）：修复边界错误，验收正常值、边界、空集及既有返回约定。
- B02 重试与取消状态联动（M）：修改执行器与调用方，验收重试次数、取消后不继续执行、错误传播；以确定性假时钟/假 IO 验收，不依赖真实网络。
- B03 批处理日志中的局部错误（O）：从多批次日志定位解析与聚合错误，验收缺陷消失、其他批次结果不变，允许正常搜索和脚本聚合。
- B04 订单修复与回归链（L）：定位金额错误→修复聚合→处理退款边界→整体验证；最终同时检查各阶段已接受的要求，不只看最后一处输出。

### 功能实现：F01～F04

- F01 配置项与默认行为（S）：新增可选配置，不传参数时保持旧行为，非法参数明确定义。
- F02 查询过滤贯穿三层（M）：同步解析器、服务与调用方，验收组合条件、空结果和旧接口兼容。
- F03 依据迁移记录实现导入兼容（O）：阅读不同版本的协议说明、真实样例和迁移记录，新增兼容导入；验收组合输入和未直接给出的边界，需求无歧义。
- F04 增量报表演进（L）：基本聚合→增量更新→去重与排序→导出；终态检查每步功能及新增步骤没有破坏旧功能。

### 重构：R01～R04

- R01 计算逻辑与渲染拆分（S）：移动职责、保持输出和输入纯度，验收基本与边界输入。
- R02 返回接口迁移（M）：同步三处消费者，验收新接口、旧业务行为和异常传播。
- R03 重复规则合并（O）：从多个相近模块与业务说明识别可合并部分，保留合法差异；验收差分行为，不能只看代码行数减少。
- R04 状态模块逐步迁移（L）：提取模块→迁移调用方→替换内部表示→移除旧适配；终态要求迁移完成且业务行为保持。

### 测试编写：T01～T04

- T01 阈值函数边界测试（S）：测试在正确实现上通过，杀死预先指定的边界变异，接受等价实现。
- T02 有状态限额测试（M）：跨调用序列验证限额、重置及拒绝路径；杀死独立状态变异，不能靠源码字符串识别实现。
- T03 日志事故转回归测试（O）：依据事故记录与规格编写行为测试，验收正确实现、相关变异和行为等价改写。
- T04 变更后的测试套件维护（L）：建立测试→响应规格变更→覆盖回归→整理最终套件；最终接受现行正确行为、拒绝指定缺陷、删除与现行规格冲突的旧断言。

### 所有题目的共同要求

1. 提供明确需求、可编辑范围、交付物和必要公开 smoke 检查；隐藏测试实现、隐藏输入、变异体与 reference。题目规格可由 agent 理解并自行编写检查，这是正常行为，不算泄露。
2. 基本题提供约 2～4 个相关模块；工程题按依赖需要提供约 6～12 个模块；O/L 类以约 12～25 个模块及必要文档/日志起步。这些是制作尺度，不是按行数验收，更不保证触发上下文处理。
3. L类不重发全部旧需求；前期用户约束可以只在历史中出现，双方都可将它记入工作区，允许正常检索和笔记。不能要求“不得保存约束”或把遗忘当成唯一失败来源。
4. O类使用与任务相关的诊断材料，重要线索分布于多处；不得填随机垃圾、强制读满全文、禁止 grep/脚本/管道、固定 agent 的工具调用路线。模型绕过大输出并成功是有效结果。
5. 每题预先定义四个等权合同组，明确每组检查哪些需求；关键合同不得用大量简单断言稀释。全题通过要求四组全过且保护约束满足；分组只作诊断。
6. 先离线证明：初始/无产物态不通过；参考解通过；至少两个针对不同错误的反例不通过。重构还需证明初始实现在“行为保持”组通过而在“迁移完成”组失败；浮点采用何种等价准则必须写入任务。
7. 理解类复现以行为执行验收，并配置缺陷侧/正确侧的等价改写，拒绝直接比较源码/哈希的产物；测试编写类同时检查正确实现、变异体、等价体。超时不算杀死变异体。等价改写提高防投机能力，不宣称可证明消除所有投机。
8. 隐藏验收在候选退出后的独立副本上运行，结果不反馈给模型。原工作区、阶段快照与候选产物保留到验收和证据归档完成。

## 4. 整题资源预算与运行协议

每题、每组、每次重复均使用同一整题预算，单任务和四阶段题都不随阶段数增发额度：

- 最多 64 个模型请求（含摘要请求）、128 个工具调用、600 秒主动墙钟。
- 累计输入加输出 token 主候选上限 2,000,000；校准备用档 1,000,000。正式只选择一个档，全题全组一致。
- 单条模型输出上限 16,384，最小输出预留 4,096；请求超时 180 秒；Bash 单次最多 30 秒；收尾 5 秒，均受整题剩余时间约束。
- 上下文目标、压缩、预览策略按第 2 节；模型真实窗口、采集/存储上限和其他策略字段四组相同。

运行器在每阶段发出前计算 episode 剩余量，按较紧约束传入 run；剩余量为零不发送。整题 watchdog 覆盖阶段间开销，工具与摘要不能在外层预算看不见的位置继续执行。计数以事件和 provider usage 为事实；估算回退明确标注，token 上限受 usage 晚到影响可能超出，报告 overshoot，不承诺费用硬上限。

任一阶段非 `completed`（包含 output_limit、max_steps、token_budget、context_overflow、timeout、取消、基础设施错误）即停止下发后续阶段。不自动 `/continue`，不因失败赠送新额度；仍在退出快照上执行隐藏验收并分别保存产物正确与运行可靠两项事实。

为每阶段保存输入合同版本、run/task ID、状态、累计与本段计数、文件快照 hash；隐藏验收只在候选完全退出后执行，可以离线复核早期快照，但不提前给模型隐藏反馈。终态应检查所有仍有效要求，撤销的要求不作为回归失败。

## 5. 校准、冻结与正式批次

### 校准：最多 40 个 episode

另建 U/B/F/R/T 各一个独立校准根问题，共 5 题，不复用正式题的初始项目、同一缺陷或仅改名变体。校准包含单任务长诊断和多阶段场景。只运行 Baseline / Full，每题每档重复 2 次，即每档 20 个 episode。

先用 2M 档，baseline 成功数按 10 次计：

- 3～8 次：预算具有初步区分空间；检查下述机制与合同条件，通过则选择 2M，不再试 1M。
- 9～10 次：只再检查预先定义的 1M 档，仍需达到 3～8 次及相同机制条件。
- 0～2 次：不进一步收紧，先检查可解性、合同与难度；本轮停止，不跑正式批次。

上述区间是制作工具，不是统计充分性判断。是否入选不看 Full 是否赢、差值是否达标；不挑选“仅 Full 成功”的题塞进正式题库。

机制条件：所选档 Full 的 10 次运行至少 6 次出现 C 的一种主动机制；其中压力压缩至少覆盖两个独立校准问题根。多阶段题至少观测一次真实旧任务裁剪，信息定位题至少观测一次真实预览截断。P以多轮请求中的系统提示稳定性和实际缓存字段核对。若某机制不足，按原因修订题型或明确缩小结论范围；不把阈值改到极低值强迫触发。

只允许这一轮预定档位选择；两档均不合格或机制不足，公开校准结果，登记 v2.1 新协议后另行校准，不无限追跑。若某题规格错误，不按某组输赢修题，先离线修正合同并使用新版本批次。

### 冻结

正式开跑前形成机器可读 manifest：20 个完整题目及每组四合同、initial/reference/验收器/隐藏输入 hash、明确模型配置、预算档、四组 resolved 配置与差异白名单、schema/prompt/规则 hash、顺序 seed、计划数、价格快照与金额额度。当前目录说明不能代替完整题目；本次设计不称为已完成预注册。

### 正式：240 个 episode

20 题 × 四组 × 三次重复。每次从独立干净工作区和独立 session 开始；按 task/repeat 构成 block，在 block 内打乱并平衡四组顺序。三次重复分布在预定时间 block；任务与顺序固定 seed `20261015`，不声称它控制模型采样或供应商缓存。串行调度，不共享候选文件；供应商缓存可能跨 session 共享，记录 cache usage 并承认无法完全隔离。

正式运行不依成功率提前停止、不追跑失败、不删预算停止。模型回显、代码、验收器或关键环境非计划改变时封存批次。整批未完成记 incomplete，公布计划/执行/缺失数，不缩分母后假称完整比较。

## 6. 六类指标与唯一主比较

### 1）成功率

主指标 `reliableSuccess`：所有阶段正常结束 AND 最终四合同组全通过 AND 保护约束满足 AND 证据可复核。

每组正式分母固定 60 个计划 episode。完成整批时，预算停止、溢出、工具策略拒绝、模型失败、基础设施错误均记主指标 0，并逐项列原因；这是评估交付可靠性，不混称纯模型能力。若存在未运行项，不虚构已运行失败，主批次标 incomplete，同时给缺失项取 0/1 的范围。

同时保留 `artifactAccepted`（退出快照正确性）、四合同组得分、已执行且排除外部基础设施故障的敏感性口径。预算停止不从主分母移出；旧 NX-40 的条件性成功率不与本批主指标混用。不得事后把基础设施故障改名为不可行来改善结果。

### 2）Model Rounds

主循环模型请求数与摘要请求数分列，并报全部模型请求总数；包括失败尝试，不能只平均赢家。各组报每 episode 均值、中位数及分布。

### 3）Tool Calls

报实际调用总数和每 episode 分布，跳过/未执行的调用单列；重试保留，不合并成一次成功。

### 4）Tool Errors

报实际执行的错误数与执行前策略/参数拒绝数、错误率及原因。取消/预算导致的 skipped 不算工具执行错误。预期的失败测试也单列，不把“主动跑测试发现缺陷”直接解释为 Harness 缺陷。

### 5）Token

输入、输出、摘要、cache-hit token 分列；provider 与 estimated 分列。报每题均值/总量，并报“全部尝试消耗 ÷ 可靠成功次数”；零成功记不可定义。缓存命中减少计费输入，不自动等于总输入 token 减少；P的资源结论可主要落在命中和费用。

### 6）Latency

报每题主动墙钟的均值/中位数/p95，另报逐请求延迟 p50/p95、摘要时间、超时次数。未闭合请求不伪造响应延迟；两臂都成功题上的耗时比较只作辅助，不能代替全任务结果。

### 比较与表述

唯一主比较是 Full−Baseline 的可靠完成率绝对百分点差。每根问题先对三次重复求平均，再对 20 根等权平均；五类各四题，因此类别权重一致。95% 区间用按类别分层、问题根成对 cluster bootstrap（10,000 次，seed `20261015`）；抽根时带走四组全部重复，不把 60 次当 60 个独立题。

预先将 +10 个百分点作为实用改善参考值。只有点估计≥+10 且区间下界>0，才称“在本题库及预算下观察到有支持的可靠完成改善”；若要声称“至少提高10个百分点”，区间下界还需≥+10。其余如实报告估计及不确定性；20 根可能不足以区分较小效应。

Context−Baseline、Full−Prompt 为C的两个条件效应；Prompt−Baseline、Full−Context 为P的两个条件效应，均属探索性，保留负向结果及可能交互。C是复合处理，不进一步归因某一种内部机制。移除旧 `spread > 0` 作为“有效性”结论的做法；任何机制为零时保留全题结果，只限制对应解释，不事后排除未触发题。

报告逐题配对结果、各类别、三次重复、两组都成功/仅Full成功/仅Baseline成功/两组都失败，以及机制触发和失败案例。不能拿第一轮 18/20 对另一组最好/最差轮 15/20；若给20题视图，每题显示0/3～3/3，主结论仍用全部尝试。

## 7. 工作量上界与付费边界

正式按2M档理论上界为 240 episode、15,360 模型请求、30,720 工具调用、480,000,000 累计 token、40 小时主动时间；1M档为240,000,000 token，其余不变。以上是极端上限，不是预计消耗、报价或交付时长。

两档校准全跑时为40 episode、2,560请求、5,120工具、60,000,000 token、6小时40分钟主动时间。校准加正式至多280 episode、17,920请求、35,840工具、540,000,000 token、46小时40分钟主动时间；按2M正式计算。另预留最多4次协议探测，每次≤8,192累计token、180秒，合计32,768 token/12分钟，不供失败任务重跑。

本次没有核对供应商现价，不给金额。付费前单独形成价格快照、校准金额上限；正式再根据校准实耗提供预计金额与保守上限并取得批次授权。模型请求、摘要、失败和缓存计费都计入，不拿token上限冒充货币硬止损。正式调度按四组block预留预算，余额不够一个完整block时不启动它。

## 8. 框架修改与独立验收边界

以下均未实施；每个步骤在开始功能开发前同步 TASKS、完成时写 CHANGES，并按 AGENTS 的验收/提交规则推进。命令名是拟新增接口，当前不能直接运行。

3. **候选环境与隐藏验收隔离**：候选工具进程只能访问题目工作区及运行所需公共依赖，reference/隐藏测试/其他候选产物不可挂载到该环境，验收由外部监督器在候选退出后执行。优先固定一个Linux隔离运行环境，provider请求由宿主适配器代理，模型凭证不传给候选Bash；四组使用同一环境。现有“验收器放在工作区外 + 应用层路径检查”不能单独满足此项，因为Bash脚本可能绕过工具路径检查。实现方式及运行镜像在该步骤落地并冻结；用候选中的Node/文件工具/Bash读取已知诱饵路径的探针证明不可访问，同时证明正常检查与回读可用。独立提交，不增加付费额度；隔离尚未验收不得进入真实模型校准。生产CLI不随评测切换运行模式。
4. **新验收合同与基本/跨模块题（10题）**：扩展 `coding-fixtures.ts` 的独立 `harnessV2Ids` 和 manifest 映射；现有 edit/repro/mutation 复用，新增通用四组读数。交付U/B/F/R/T的S和M，覆盖行为复现等价体、重构差分、变异反例。以完整验收合同为边界，不能只交没有首个使用者的空抽象。独立提交。

7. **V2报告与冻结清单**：独立 `eval:v2-report`，实现六指标、失败口径、配对、根级区间、缺失数据与输入hash；人工可算的合成数据证明统计正确，不能复用旧四格的spread判断冒充新结论。独立提交。
