## R 对 R-serial（唯一干净的对照）

- 成功率相同：都是 4/4。
- `parallel-composite`（第一波两个子任务可并行）：R 的墙钟 19.5 s / 42.3 s，R-serial 29.2 s / 48.4 s，两次都是 R 更快。
- `single-repair`（只有一个子任务，并发数不起作用）：R 19.0 s / 13.8 s，R-serial 45.0 s / 20.3 s。这里不可能有并行收益，差异仍然很大，说明单次墙钟受模型响应波动影响明显；因此上一条的速度差不能确定地归因于并行。
- 请求数与费用相近（R 56 次 / $0.032，R-serial 65 次 / $0.042）。

## 混杂因素（为什么 S/D 与 R 不可比）

1. **规格不对称（夹具问题）。** `parallel-composite` 的隐藏验收器要求 `names` 覆盖**全部**人员；这条约定只写在固定计划的 `st-3` 目标里，只有 R/R-serial 的 worker 看得到。S/D 只拿到根目标和只测一个例子的公开冒烟检查，四次都实现成“去重后的人员名单”——这是对目标的合理解读，公开检查也能通过。S/D 在 `st-3` 上的失败是本批次夹具设计的不对称，不是单 Agent 能力不足的证据。
2. **提示缓存配置不同。** 编排 worker 以冻结的上下文布局与运行时钟运行；本批次的 S/D 执行器沿用 harness 缺省（实时时钟），提示前缀每轮变化。缓存命中占输入的比例：S/D 2–3%，R/R-serial 73–91%。费用差异（$0.03 对 $0.11）主要来自这里，延迟也可能受影响。
3. **D 没有委派。** D 的 4 次运行都没有调用 `delegate_tasks`，因此 D 实际度量的是“S 加一个未使用的工具”，不能说明只读委派的作用。
4. **样本量。** 每任务每臂 2 次，不做显著性判断。

## 本批次能说明什么

- 付费执行通道本身可用：冻结 manifest、协议探测、在途预留金额守卫、按 worktree 的隔离、隐藏验收与报告都在真实模型下按设计工作，16 runs 零基础设施错误。
- 在同一计划下，编排的并行与串行版本都能稳定完成这两个小任务。

## 若要回答“编排是否更好”，下一批需要先改

1. 让 S/D 与 R 拿到同等的规格：要么把子任务约定写进根目标，要么让 R 用 planner 而不是人工计划。
2. 四臂使用相同的上下文布局与运行时钟（或把缓存配置作为显式变量）。
3. 为 D 选择会触发只读调查的任务，或在报告中把“未委派”单列。
4. 增加重复次数，并补上 §14.3 的冲突型与负对照任务。

以上任何改动都构成新批次，需要重新冻结 manifest 并单独授权。
